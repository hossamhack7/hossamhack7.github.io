# API Route 404 Fix Documentation

## Issue Description
The Gemini Command Center WordPress plugin was experiencing 404 errors when making API calls from the frontend JavaScript to the WordPress REST API endpoints. The error message was:

```
"No route was found matching the URL and request method."
```

## Root Cause
The issue was caused by an incompatibility between the URL format generated by WordPress's `rest_url()` function and the expected format for `@wordpress/api-fetch`.

### Problem Details:
1. **Original URL format (using `rest_url()`):**
   ```
   https://example.com/index.php?rest_route=/gemini-cc/v1/
   ```

2. **Expected URL format (for `@wordpress/api-fetch`):**
   ```
   https://example.com/wp-json/gemini-cc/v1/
   ```

3. **The Issue:**
   - `rest_url()` can return different URL formats depending on permalink settings
   - When pretty permalinks are disabled or rewrite rules have issues, it returns the `?rest_route=` format
   - `@wordpress/api-fetch` expects the standard `/wp-json/` format
   - The middleware was not properly handling the `?rest_route=` format

## Solution Implemented

### 1. Fixed API URL Construction
**File:** `includes/class-assets-loader.php`

**Before:**
```php
'api_url' => esc_url_raw( rest_url( 'gemini-cc/v1/' ) ),
```

**After:**
```php
'api_url' => esc_url_raw( home_url( '/wp-json/gemini-cc/v1/' ) ),
```

### 2. Updated Debug Output
**File:** `gemini-command-center.php`

Updated the debug page to also use the consistent `/wp-json/` format for displaying REST URLs and testing API connections.

### 3. Enhanced Error Logging
**File:** `src/index.js`

Added detailed error logging to help identify URL format issues in the future:
- Added URL construction analysis in error logs
- Added specific guidance for 404 errors
- Added validation of API URL format

### 4. Improved Debug Information
**File:** `includes/class-api-registrar.php`

Enhanced the debug route registration logging to provide more detailed information about:
- Route registration status
- Expected URL formats
- Server request details

## Benefits of This Fix

1. **Consistent URL Format:** Always uses the standard `/wp-json/` format regardless of permalink settings
2. **Better Compatibility:** Works reliably with `@wordpress/api-fetch` middleware
3. **Enhanced Debugging:** Provides better error messages and debugging information
4. **Future-Proof:** Less likely to break due to WordPress configuration changes

## Testing the Fix

### Method 1: Using the Debug Script
1. Upload `debug-api.php` to your WordPress root directory
2. Visit `https://your-site.com/debug-api.php` in your browser
3. Check the test results for route registration and API connectivity

### Method 2: Browser Console
1. Open the Gemini Command Center admin page
2. Open browser developer tools (F12)
3. Check the console for API connection test results
4. Look for successful API calls instead of 404 errors

### Method 3: WordPress Debug Logs
1. Enable `WP_DEBUG` in `wp-config.php`
2. Check the debug log for "Gemini CC: Status route registered successfully"
3. Verify no "API Request Failed" errors in the logs
